## What was found and fixed on the way

| Problem                                                                                                 | Root cause                                                                                                                         | Fix                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every Playground E2E test failed: "WebWorker failed to load at …playground-worker-endpoint-blueprints…" | Playwright's `userAgent` override (from the `devices` presets) stops the remote's module worker loading; viewport presets are fine | `withoutUserAgent()` in `playwright.config.ts`; documented in TESTING.md section 5 and ADR 0001                                                     |
| Boot spun forever when the remote showed its own error page                                             | `startPlaygroundWeb()` never rejects                                                                                               | 120 s boot timeout in `createWebPlaygroundService` (TC-PG-013e)                                                                                     |
| WebKit: boot failed when "Keep files between reloads" was on                                            | WebKit refuses OPFS to the cross-origin Playground iframe                                                                          | Persistence is a reported capability (`on` / `off` / `unavailable` + reason); the panel says "Files will not be kept"; TC-PG-006 asserts the matrix |
| Firefox: console guard failed on a `sw.js` error from the remote                                        | Upstream service-worker message for an empty-URL request inside WordPress                                                          | One commented allow-list entry in the E2E fixture                                                                                                   |
| `TC-FND-009a` (dark-mode axe) failed 9/9 after the panel was added                                      | White text on the dark-theme accent: contrast 2.64:1                                                                               | `--color-on-accent` token; axe clean in both themes                                                                                                 |

## Independent review

A separate reviewer agent that had not seen the implementation checked the diff against the coding standards and the
test cases. It confirmed the boundaries, the standards and the docs, and found three must-fix items, all fixed with
tests first: the TC-PG-004 exit-code assertion was a tautology (`expect.not.stringMatching` on a number), `writeFile`
created a stray folder for a path without a slash (TC-PG-014m), and the TC-PG-006 row did not describe the WebKit
expectation. Also taken: a guard against booting twice plus disposal of the previous connection on reboot
(TC-PG-014l), the dead `failBoot` now has a test (TC-PG-009m), stderr asserted in TC-PG-011c, shared byte decoding in
`request()`, `useId` for the panel heading, a type guard for the PHP select, and TSDoc on exported lib types. Three
items are recorded in the plan as carried into Phase 4 (abortable boot, "what to do next" and copy-logs in the error
state, narrower lint exemption for the integration harness). All checks were run again after the fixes.
