| Problem                                                                                                    | Root cause                                                                                                                | Fix                                                                                                                                 |

## Independent review

A separate reviewer agent that had not seen the implementation checked the diff against the coding standards and
the test cases. It confirmed the path validation, the tab bookkeeping, the feature boundaries and that every TC-WS
case has a matching test, and found four must-fix items, all fixed with tests first: dialogs opened from the context
menu lost focus to the tree row behind them, so Escape did nothing (TC-WS-008g); deleting an expanded folder left
focus on `body` (TC-WS-008h); the palette's "No matching commands" row inside the listbox was an axe-critical
`aria-required-children` violation (now a status line outside the list, scanned by TC-WS-012); and this test-run
record was still missing. Also taken: a drag-state ref written with each update (not in an effect), Shift ignored
by the shell shortcuts and shortcuts paused while the close dialog is open, splitters persisting on release instead
of every move (`onCommit`, TC-WS-015c), Tab kept inside the palette, the context menu clamped to the viewport,
modifier combinations ignored by the tree keys, pure helpers moved to `tree-helpers.ts`, and preferences reading the
storage before memory. All checks and the e2e run were repeated after the fixes.
